# Spec: Phase 10, language-model agents (Claude API)

Status: **implemented** (2026-10-12). Pilot, frozen analysis plan (hash `83df7591d1de`), main runs (47 988 calls, $31.94 charged; $33.50 with the pilot, of the $150 cap) and the cached-rerun check done; results below (all exploratory). Run guide: [RUN.md](RUN.md). Part of the multi-agent plan: [../README.md](../README.md). Builds on Phases 5-9: [../phase9/README.md](../phase9/README.md).

## Goal

Repeat the key experiments with real language-model agents, on a small API budget, and ask whether what the numpy agents showed carries over.

1. **Two text tasks with the same structure:** *text foraging* (the Phase 8 benchmark world described in words, with named locations) and a *task board* (each "patch" is a seeded puzzle with a checkable answer; crowding = duplicate work, travel = switching cost, moving patches = expiring subtasks, danger = penalty for a wrong answer).
2. **The four Phase 7 channels, mapped one to one,** with Claude Haiku 5.5 agents: team sizes 1, 2, 4, 8, five seeds, about 50 turns per agent.
3. **Bitter Lesson test:** the same harness comparison on the task board with Claude Sonnet 5.5 (sizes 1 and 4, three seeds): does a channel's benefit shrink with a stronger model?
4. **Tokens as compute:** team welfare against total tokens, plus an equal-budget arm (the same total agent-turns split across team sizes).
5. **Numpy predicts LLM?** Spearman correlation between numpy and LLM team welfare over the 16 (channel, size) cells of each task, with a bootstrap interval over seeds.
6. **Prompt-only tests of Phases 8-9:** incentive framing (scored on own result, on the team's, or own plus discovery credit), persistent notes across episodes, memory settings as context management, and one scripted liar among the agents.
7. **Ready to train on:** both tasks behind the Phase 5 interface, with checkable rewards, individual / team / difference reward options and JSONL trajectory logs. No training is done (plan part 4).

Phase 10 adds the `anthropic` SDK as an optional extra; the core package and every normal test run without it and without network access.

**Main acceptance tests:** (a) normal tests use a scripted fake client and never call the API; (b) every live response is cached on disk, so a rerun is exact and free; (c) a run stops before it can exceed the spending cap, and its cost is recorded; (d) both tasks pass hand-checked examples and the Phase 5 world protocol; (e) the pilot fixes the task-board difficulty and the per-turn settings before the main runs, and the analysis plan is committed before them.

## What Phases 5-9 and the API give us (the facts the design depends on)

| Piece | Fact | Consequence for Phase 10 |
|---|---|---|
| Phase 5 `runTeam` / world protocol | Event queue; a world offers `reset`, `observe`, `apply`; members act one at a time | An LLM agent is a `Member` whose `event` is one API call; the text tasks wrap worlds that implement the same protocol, so the logs and the ledger carry over; runs use `runTurns`, the same event queue with a turn budget per member |
| Phase 8 `benchWorld`, metrics, `runGrid` | 64-location ring, 16 patches moving every 40 s; welfare, IFD distance, belief diversity; deterministic parallel runner with CSV output | Text foraging wraps `benchWorld`; metrics are reused; episodes run in parallel processes through `runGrid` |
| Phase 7 channels, Phase 9 agents | `Blackboard`, `MessageBus`, `Lead`; scripted `Liar` | Same channel objects behind the text; the lead stays the numpy baseline coordinator; the liar is scripted, not prompted |
| Phase 8-9 results | Blackboard best from 4 agents up; `messages` adds nothing; one liar costs 4-7% on the blackboard (H3) | The numpy cells to compare against exist; the LLM liar arm asks whether H3's direction holds |
| Models (Claude API, cached 2026-10-06) | Smallest current: **Claude Haiku 5.5** (`claude-haiku-5-5`, $0.10 / $0.50 per million input / output tokens for prompts up to 100K); mid-size: **Claude Sonnet 5.5** (`claude-sonnet-5-5`, $2 / $10). Both: adaptive thinking on by default (billed as output), `effort` low to max, **non-default sampling parameters (temperature) rejected with a 400**, no assistant prefill, forced tool choice rejected on Sonnet 5.5, 512-token minimum cacheable prefix, editing earlier turns invalidates replayed thinking. Haiku 5.5 has no server-side refusal fallback | Temperature 0 is not available: the response cache is what makes reruns exact; actions come back as structured JSON (`output_config.format`), not forced tool calls; each turn is a fresh single-message prompt (no replayed assistant turns), so memory settings cannot trip the history-editing check; prices are re-checked before any live run |

## Decisions

| ID | Question | Answer |
|----|----------|--------|
| L1 | Models (plan Q6) | **Claude Haiku 5.5** (`claude-haiku-5-5`) for every grid; **Claude Sonnet 5.5** (`claude-sonnet-5-5`) for the reduced Bitter Lesson grid and its pilot. Adaptive thinking on (the default), `effort = 'low'` for both (pilot: medium effort did not raise Haiku's solve rate and once ran to the token limit), the same per-turn `max_tokens` (8000, pilot) for both |
| L2 | Spending cap (plan Q6) | **Decided by the user (2026-10-11): $150.** Confirmed before any live run (the gate before T7 checks credentials); the estimate in design-low-level section 8 was about $50-70 for everything; spent: $33.50 (pilot and main runs). A hard cap in config: a run is refused if its estimate exceeds what is left, and stopped when its recorded cost reaches the cap |
| L3 | Reproducibility | Sampling parameters cannot be set on these models, so **the on-disk response cache is the only source of exact reruns**: every request is keyed by a hash of its full parameters; a cached response is replayed at no cost. Seeds control the world, the puzzles and every scripted draw; live reruns are not expected to match |
| L4 | Turn format | Each turn is **one request**: the static rules and world description in the cached `system` prompt, then one user message whose content blocks are the agent's rendered history (append-only, one block per past turn, the cache breakpoint on the last) and the current observation. No assistant turns are replayed, so thinking blocks are never resent and the history-editing check cannot fire |
| L5 | Actions | **Structured output** with one fixed JSON schema per task (`output_config.format`): an action name, a target (location or subtask name), an optional report (a location and a value; on the task board, a subtask and a `working` or `solved` claim), and a short `notes` field the memory settings can use. Names are free strings checked in code (a fixed schema keeps the cached prefix stable); an unknown name, a `max_tokens` stop or a refusal becomes "stay" (or "wait") and is counted as an invalid action |
| L6 | Refusal fallbacks | **Off** (confirmed by the user, 2026-10-11), deliberately: a server-side fallback would answer with another model, which confounds the model-size comparison. Refusals are rare in these tasks; each is recorded (`stop_details`) and treated as an invalid action |
| L7 | Text foraging | `benchWorld(tStay=5)` (Phase 8, with 5 s stays: a deviation decided by the user after the pilot, 2026-10-12, applied to the numpy comparison too) with its 64 locations renamed from a seeded word list; each turn shows the agent its location, last reward, the travel time to every location and the channel contents; actions "stay" or "go <name>". About 50 turns per agent (events, as in Phase 5) |
| L8 | Task board (plan Q7) | Subtasks are **seeded "find x" puzzles**: a short generated integer function `f` and a target `y`; the answer is an `x` in a stated range with `f(x) == y`, checked by evaluating `f` (our generated code, never model code). The board holds more subtasks than agents; subtasks appear and expire on a schedule; only the first correct answer scores its value; opening a subtask costs a turn (switching cost); a wrong answer costs a penalty. Difficulty (function depth, range) was to be set in the pilot so Claude Haiku 5.5 alone solves 30-70%; the pilot found no such level (see Pilot results), and the user chose the harder board with a larger `max_tokens`: **difficulty 8** (9 operations, answers below 12 800), solve rate 0.89 |
| L9 | Channels | `none`; `blackboard` (reports the agents choose to post: in foraging the mean reported value per location with a weight that fades with age, as in Phase 7; on the task board the latest claim per subtask with its author and age); `messages` (an agent's report goes to 2 random teammates, at most once per period); `hierarchical` (a numpy coordinator, the Phase 7 `Lead` for foraging and a greedy `BoardLead` for the task board, shows each agent a suggested target; the agent is free to follow it). Reporting is voluntary, so whether agents share is itself measured |
| L10 | Memory (context management) | Default **full history** (append-only, cache-friendly); exploratory settings: last 8 turns, notes only (the agent's own running `notes` field instead of history) |
| L11 | Budgets | Main grids: **50 turns per agent** (the fixed-world-time analogue). Equal-budget arm (the plan's "equal token budgets"): 200 agent-turns per team, split across team sizes (200, 100, 50, 25 turns), with tokens per turn capped by `max_tokens`, so total tokens are roughly equal; text foraging, `none` and `blackboard`, 3 seeds. Actual team tokens are recorded per run and plotted |
| L12 | Numpy comparison | For text foraging, the Phase 8 `CommBandit` / `LeadFollower` teams on the same worlds, sizes and turn budgets; for the task board, numpy bandits on a simulated board whose solve probabilities are the pilot's measured solve rates. Numpy cells run with the same turn-limited loop (`runNumpy`). Spearman correlation over the 16 (channel, size) cells per task, bootstrap CI over seeds |
| L13 | Analysis plan | Fixed and committed before the main runs (`ANALYSIS_PLAN` in code, its hash in every report). Phase 10 has no new confirmatory test (the plan's confirmatory family ended with H3); its results are exploratory but pre-specified: metrics, cells, seeds, the Spearman comparison and the model-size contrast |
| L14 | Belief diversity | Text foraging only (on the task board every subtask's value is shown, so there is nothing to estimate): elicited once per agent at the end of each run (one extra call: "your estimate of each location's value"), so Phase 8's diversity and herding metrics carry over at small cost. IFD distance and recovery time also apply to text foraging only; welfare, discoveries and liar robustness apply to both tasks |
| L15 | Liar arm | One **scripted** liar (the Phase 9 rule; on the task board it posts false `solved` claims on open subtasks and `working` claims it does not follow) among 3 LLM agents, blackboard and messages, both tasks, 3 seeds: does one liar cost the LLM team more on the blackboard, as H3 found for numpy agents? |
| L16 | Framing and persistence | Text foraging, blackboard, 4 agents, 3 seeds. Framing: three prompt variants of the scoring sentence (prompt only; rewards stay individual); measured by welfare, exploration share per agent, report share and the free-riding index (with Phase 9's caveat that the index does not flag free-riders as defined). Persistence: 4 episodes of 25 turns, episode `e` on world seed `10 000 + 100 seed + e` (as in Phase 8 study B); agents keep or do not keep a `lessons` note: an agent's last `notes` of an episode, shown in its system prompt in the next (no extra call) |
| L17 | Execution | Episodes run in parallel processes through Phase 8's `runGrid` (synchronous client per process, `min(8, cpu)` processes); the SDK retries 429 and 5xx; concurrency is the demo's `WORKERS` setting, to respect the organisation's rate limits |
| L18 | Training-ready packaging | `TeamPatchWorld` and `TaskBoardEnv` implement the Phase 5 world protocol; `TextForagingEnv` and `TextBoardEnv` add text observations and `parse`; individual / team / difference rewards (foraging: the Phase 6 schemes; task board: team = each solve's value shared equally, difference = individual, since only the first correct answer scores); all experiments use individual reward; JSONL logs of every turn (observation text, response text, parsed action, reward, tokens, cost) |
| L19 | Seeds | LLM main grids 500-504; Sonnet grid 500-502 (the same worlds as the Haiku cells it is compared with); arms 600-699; pilot 1000-1099 |
| L20 | Plan deliverable | **Part of this phase (user, 2026-10-11):** task T10 writes `nbs/demo_multiagent.ipynb` and `results/multiagent/REPORT.md` around the headline question, from the saved Phase 8-10 results (no rerun) |

The pilot (task T7) fixed the provisional settings; the analysis plan was committed after the pilot and before the main runs.

## Notes from the offline implementation (for the pilot)

- **Turn budget vs world time.** With 50 turns per agent and 1 s stays a text-foraging run spans under two of `benchWorld`'s 40 s patch-move periods (the numpy teams are also still exploring at 50 turns). The pilot confirmed it (LLM runs covered 19-32 s in 30 turns), and the user chose 5 s stays (see Pilot results).
- **Module split.** To stay under 200 lines per file, the board's channels and numpy agent are in `board_agents.py`, the text board in `llm_board.py`, the numpy comparison in `llm_compare.py`, the figures in `llm_figures.py`, and the offline `FakeClient` and `fakeReply` in `llm_fake.py` (design-high-level).
- **Costs on cache hits.** A cached reply keeps the cost of the call that produced it (rows do not depend on the cache, so reruns are byte-identical) and is not charged to the budget; cache hits are counted per mode in `metrics.json` (after the main runs, rows and turn logs stopped carrying cache flags, which differ between a live run and a rerun).
- **Provisional estimate.** With the provisional token profile, the main runs were estimated at about $34 (Haiku about $12, Sonnet about $22).

## Results (task T9, 2026-10-12; exploratory)

All grids ran within the cap: 47 988 API calls (Claude Haiku 5.5 44 988, Claude Sonnet 5.5 3 000), of which 45 809 were sent live and the rest were identical requests served from the cache; $31.94 charged ($33.50 with the pilot) (row costs sum to $32.68: a reply served from the cache keeps its original cost but is not charged again); 10.6 h with 8 processes; no grid was stopped. Haiku made 3 invalid actions in all grids (3 `max_tokens` stops in 30 300 main-grid calls) and no refusal; Sonnet: 3.4% invalid (101 `max_tokens` stops, 1 refusal) and $16.99 of the cost. About 80% of input tokens were read from the prompt cache. Numbers are means over seeds with 95% bootstrap intervals; full tables in `results/multiagent/llm/full/report.md`.

**1. Task board: channels matter, and more so for bigger teams.** Without a channel, welfare per agent-turn falls from 0.99 (N = 1) to 0.72, 0.50 and 0.35 (N = 2, 4, 8): agents pick the same high-value subtasks, and at N = 8, 60% of all turns are duplicate work (opening or answering a subtask someone else solved). The blackboard of claims removes that almost completely (under 1% duplicate turns; welfare 0.94-0.99 at every size; agents posted a claim on about 98% of turns although sharing was voluntary). Benefit over no channel at N = 2, 4, 8: blackboard +0.23, +0.46, +0.60; messages +0.24, +0.34, +0.21 (two recipients cannot cover a team of 8); the numpy coordinator +0.13, +0.33, +0.35 (it suggests the highest-value subtask, which LLM agents often override). All at N >= 2 have intervals above 0.

**2. Model size (board, N 1 and 4).** At N = 4 every channel's benefit was smaller with Sonnet 5.5 than with Haiku 5.5 (blackboard +0.34 vs +0.46, messages +0.23 vs +0.34, lead +0.13 vs +0.33), in the direction of the Bitter Lesson hypothesis; averaged over N 1 and 4 (the pre-specified contrast) the differences are -0.03 [-0.08, 0.01], -0.09 [-0.17, 0.04] and -0.12 [-0.30, 0.01]: **unclear** (3 seeds). This is not "the stronger model needs less help": at `effort = low`, Sonnet answered far less carefully than Haiku (5.7 wrong answers per solo run vs 0.7; 24.7 vs 2.7 in a team of 4 with the blackboard), so its smaller channel benefit comes with lower welfare overall. Model size is confounded with how much each model reasons at the same effort setting.

**3. Text foraging: noisy, and LLM teams do not follow the numpy pattern.** Welfare per agent-turn lies between 0.7 and 1.5 in every cell with wide intervals; no channel helps reliably. At N = 8, the blackboard and messages *hurt* (-0.34 [-0.48, -0.13] and -0.21 [-0.36, -0.07]): with the blackboard, agents explored less (32% of turns moving to an unreported place vs 53% without a channel) and their beliefs were less diverse (0.12 vs 0.17): the herding Phase 8 found (H2, lower diversity with a blackboard), here with a welfare cost. LLM foragers did far better than the numpy bandits on the same 50 turns (numpy welfare -0.37 to +0.01: still exploring), and recovery after patch moves was rarely reached within a 40 s move period (`rmrt` 28-39 s against a 40 s censoring limit).

**4. Numpy predicts LLM?** Spearman's rho over the 16 (channel, size) cells: **board 0.75 [0.55, 0.93]**, **foraging 0.02 [-0.47, 0.45]**. On the board, where the channel's job is to prevent duplicate work, the cheap numpy model ranks the cells as the LLM teams do; in foraging, where LLM agents reason about reports in ways the bandits do not, it does not.

**5. Tokens as compute.** Team welfare grows with the team's total tokens (about 1.5 x 10^5 to 1.5 x 10^6 per run), but mostly because bigger teams make more calls: per agent-turn it does not grow. At an equal budget of 200 agent-turns (foraging), welfare per agent-turn is highest with 2 agents (no channel 1.43 [1.08, 1.72], blackboard 1.18) and falls to 0.85-0.86 at 8; splitting the same budget over more agents did not pay.

**6. Prompt-only arms (foraging, blackboard, N = 4, 3 seeds; differences from the control).** Framing: scoring on the team's total (-0.10 [-0.40, 0.18]) or own plus discovery credit (-0.07 [-0.18, 0.10]) changed neither welfare nor exploration share (+-0.03), report share (+0.01 [-0.06, 0.09], -0.05 [-0.16, 0.01]) or the free-riding index (+0.03 [-0.61, 0.66], +0.14 [-0.19, 0.59]). Memory: last 8 turns -0.19 [-0.60, 0.47]; notes only **-0.36 [-0.61, -0.13]** (forgetting the turn history hurts; it saved only 13% of input tokens). Persistence: carrying an agent's last notes into the next world did not help (episode 4: -0.31 [-0.70, 0.08]); welfare rose over the episodes with or without lessons (different worlds, not learning). Liar (one scripted liar among 4): honest welfare fell by 0.56 [-0.09, 1.06] per agent-turn on the foraging blackboard and 0.27 [-0.61, 0.94] with messages (same sign as H3, intervals include 0); on the board the liar's false claims cost almost nothing (+0.03 and -0.02), because a false "solved" claim is checked against the board within a turn, yet the blackboard-minus-messages loss is positive (+0.05 [0.02, 0.10]), as H3 found.

**Caveats.** Three to five seeds per cell, so most foraging intervals are wide. Every reply is a single sample; identical requests share one cached reply (2 173 of 47 988 calls: for example agent 0's first turns in teams of different sizes, or the first episode of both persistence arms), which pairs those cells like common random numbers. Two rows of the live run differ from the cached record in token counts only (two processes sent the same request concurrently; fixed by first-writer-wins caching after the run); the reported outputs are the cache-consistent ones. Deviations from the plan are listed under Pilot results; the plan's `cacheHit` metric is reported per mode in `metrics.json` (`cacheHits`), not per row, so that rows do not depend on the cache.

### The figures in plain language

- **`welfare.png`: does a team do better with a way to share information?** Each line is one way of sharing (none, a shared board, messages to two teammates, a coordinator); the height is how much each agent earned per turn, for teams of 1 to 8. On the task board (right), the grey "no sharing" line drops steeply as the team grows: agents keep working on the same puzzles and only one of them can score. The blue shared-board line stays flat near the top: posting "I'm working on T5" lets everyone else pick something else. In foraging (left) the lines cross and the error bars are wide: no way of sharing is reliably better.
- **`model_size.png`: does a smarter model need less help?** Each pair of bars is how much a sharing method helped on the board, for the small model (blue, Haiku) and the bigger one (orange, Sonnet), alone (N = 1) and in a team of 4. Alone, sharing does nothing (there is no one to share with). In a team of 4, it helped the bigger model less every time. But the bigger model also made many more careless mistakes at the low effort setting, so this is not clean evidence that stronger models need less coordination.
- **`tokens.png`: do more tokens buy more?** Left: each dot is one run; further right means more text processed, higher means more earned by the whole team. More tokens go with more earnings, but only because bigger teams make more calls. Right: the same total budget (200 turns) split across 1, 2, 4 or 8 agents; two agents did best, and splitting further did not help.
- **`numpy_vs_llm.png`: can a cheap simulation predict the expensive one?** Each dot is one (sharing method, team size) cell: across is the simple numpy agents' score, up is the language-model agents' score. On the board (right) the dots line up (rank correlation 0.75): where the simple agents do well, so do the LLM agents. In foraging (left) they do not (0.02).
- **`arms.png`: do small prompt changes matter?** Each dot is a difference from the standard set-up, with its uncertainty bar; dots whose bars cross the vertical line show no clear effect. Telling agents they are scored on the team's total, or rewarding first discoveries, changed nothing clear. Keeping only notes instead of the full history of past turns made agents earn less. One lying teammate hurt foragers on the shared board most (dot right of zero), but its bar is wide.
